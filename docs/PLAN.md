## 3. Дефекты из аудитов

### Важные

- [ ] `pet/app/pet_service.go` — `State()` при промахе кэша создаёт и сохраняет питомца: операция чтения имеет побочный эффект записи. Сделать чистым чтением
- [ ] `pet/app/pet_service.go` — `cache.Set` внутри транзакции: сбой Redis откатывает успешную запись в PostgreSQL. Перенести после коммита
- [ ] `shared/events/bus.go` — паника подписчика роняет HTTP-хендлер (доставка синхронная). Обернуть каждый вызов в `recover()`
- [ ] `shared/events/bus.go` — ошибки подписчиков только логируются: при сбое начисления XP пользователь получит успешный ответ, но опыт не начислится и не восстановится
- [ ] `item/app/add_photo.go` — гонка на лимите фото: два параллельных запроса проходят проверку, коллизия позиции гасится `ON CONFLICT DO NOTHING`, хендлер отдаёт `201 Created` на несохранённое фото
- [ ] `item/app/add_photo.go` — файл пишется на диск до транзакции: при откате остаётся сирота. У `PhotoStorage` нет метода удаления, при `DeletePhoto` файл остаётся на диске и доступен по URL
- [ ] `shared/apierr` — для 404/403/409 в ответ уходит `err.Error()` с внутренней цепочкой («load item: item not found»), раскрывая имена операций
- [ ] Фото раздаются nginx в обход Go: фотография объявления в статусе `draft` доступна любому, кто знает UUID
- [ ] `item/app/change_status.go` — `photoCount` глушит ошибку и возвращает `0`, из-за чего питомец получает XP по неверным данным
- [ ] Мягко удалённый пользователь (`deleted_at`) продолжает копить XP — `Service.State` не проверяет флаг
- [ ] nginx логирует query-строку: JWT из `/api/v1/ws?token=` попадает в `access.log`. Отключить логирование для этой локации
- [ ] Расхождение политик: при пустом `ALLOWED_ORIGINS` CORS молча подставляет `http://localhost:3000`, а WebSocket разрешает только same-origin
