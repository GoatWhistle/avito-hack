# Финальный спринт: план до идеального проекта

Ответ на фидбек организаторов: 1) киллер-фича, 2) доп. функционал + тестирование, 3) серьёзный ответ на инцидент с провокационными объявлениями.

**Главная развязка плана.** Хотфикс, закрывший инцидент, полностью отключил публикацию объявлений — но именно связку «действия с объявлениями → прокачка» организаторы отметили как сильную сторону, а квест `publish_one` стал невыполним. Значит, публикацию нужно не прятать, а вернуть безопасно. Это превращает проблему в фичу: модерационный конвейер с ИИ — одновременно ответ на инцидент, «интеграция ИИ» из критериев и бизнес-ценность (Trust & Safety — реальная боль Авито).

---

## P0 — Безопасный публичный прод (ответ на инцидент)

Сделано: публикация вернулась в репозиторий как постоянное поведение системы — без env-переключателя, без ручной модерации, без форков кода на сервере.

- [x] **ИИ-модерация как обязательный шлюз `moderation → published`.** Владелец больше не может опубликовать объявление напрямую — `publish` убран из доменных переходов (`domain/status.go`) и из владельческих действий (`app/change_status.go`). Единственный путь: `submit` (draft → moderation) синхронно запускает `ModerateItemHandler`, который прогоняет объявление через `ModerationProvider` (интерфейс в `domain/moderation.go`) и либо переводит его в `published` сам, либо оставляет в `moderation`.
- [x] **Фото проверяются тем же вызовом.** `ModerateItemHandler` читает файлы всех фото объявления с диска (`LocalPhotoBytesLoader`), кодирует в base64 data URL и передаёт вместе с заголовком/описанием в один vision-запрос к ИИ — текст и изображения проверяются атомарно, не двумя независимыми пайплайнами.
- [x] **Fail-closed без исключений.** Реализация — `OpenRouterModerationProvider` (`infra/openrouter_moderation.go`): нет ключа, таймаут, не-200, битый JSON от модели — всё схлопывается в вердикт `unavailable`, объявление остаётся в `moderation` навсегда. Ручной модерации нет вообще, как и просил заказчик — это осознанное продуктовое решение, не пробел.
- [x] **Защита от prompt injection.** Системный промпт явно инструктирует модель трактовать заголовок/описание как непроверенные ДАННЫЕ для анализа, а не как инструкции, даже если текст выглядит как команда модели. Ответ форсится как компактный JSON (`{"verdict", "reason"}`), парсер не исполняет ничего из ответа модели.
- [x] **Причина отказа видна владельцу.** Каждый вердикт пишется в `item_moderation_log` (миграция `00017`) с provider/reason/verdict. `GetItemHandler` подмешивает последнюю причину отказа в ответ (`moderation_reason`), фронт показывает её в `ItemDetailScreen` вместе с подсказкой «исправьте и отправьте повторно».
- [x] **Аудит SQL-инъекций.** Полный проход по бэкенду (364 файла): весь SQL параметризован через pgx `$1,$2...`, конкатенации пользовательского ввода в запросы нет. Точечно усилена валидация длины `Attributes` (map ключей/значений) — не инъекция, а защита от раздувания хранилища.
- [x] Rate limit per-IP на регистрацию и на все write-эндпоинты — уже был в проекте (`shared/middleware/ratelimit.go`), подтверждён при аудите, доработки не потребовалось.
- [ ] **Прозрачность.** Раздел README «Trust & Safety»: что случилось, какие слои защиты, почему это устраняет риск повторения (не разовый бан, а системный гейт на каждое объявление). Ещё не написан.
- [ ] **Регенерировать `docs/openapi.yaml`** из обновлённых swag-аннотаций (`write_handlers.go`) — источник правды (Go-комментарии) уже обновлён, файл документации — нет; технический долг, не блокирует работу.

### P0.1 — Seed-объявления неприкасаемы, ре-верификация при правках

По требованию: демо-креды и публичный прод остаются как есть (жюри должно видеть все стадии без регистрации), но seed-контент теперь физически защищён от порчи демо-пользователями, а изменение уже опубликованного объявления не обходит модерацию.

- [x] **Seed-объявления нельзя ни изменить, ни снять с публикации.** Миграция `00018`: `items.is_seed`, весь контент на момент миграции помечен `is_seed = true`. В domain (`item_behavior.go`) `Update`, `SubmitForModeration`, `MarkSold`, `Archive`, `Restore` отказывают на seed-объявлениях (`errSeedImmutable`, 409). Доступны только просмотр и избранное.
- [x] **Ре-модерация при правке published-объявления.** Изменение title/description (`Update`) или фото (add/delete) переводит `published → moderation` и сбрасывает `ai_verified`, затем синхронно (как при `submit`) прогоняется через `ModerateItemHandler`. Изменение только цены/атрибутов ре-модерацию не триггерит.
- [x] **Бейджи источника.** `is_seed` → бейдж «От платформы» (серый, `Store`-иконка), `ai_verified` → «Проверено ИИ» (акцентный, `ShieldCheck`-иконка) — на карточке, в списке «Мои объявления» и на странице объявления. Компонент `ItemSourceBadge.tsx`.

## P0.2 — Security-аудит и фиксы (2 широких + 1 прицельный по модерации)

Два независимых полных аудита сайта (10+ подагентов на аутентификацию/IDOR, race conditions, инъекции/JWT/mass assignment, WS, промокоды, секреты/инфра, загрузку файлов, timing/CSRF, Redis/seed/зависимости) + прицельный аудит фичи модерации. После каждого раунда — фиксы.

**Найдено и исправлено:**

- [x] **CRITICAL — демо-креды и прод-ссылка в README.** Осознанно оставлены (жюри должно видеть прод без регистрации), но seed-объявления теперь защищены от порчи (см. P0.1) — компрометация демо-пароля больше не даёт возможности испортить витрину.
- [x] **HIGH — `/metrics` без авторизации.** Добавлен опциональный `METRICS_TOKEN` (Bearer, constant-time сравнение) + rate limit на сам эндпоинт. Пусто по умолчанию для локальной разработки, прод может задать токен.
- [x] **HIGH/MEDIUM — обход rate limit через X-Forwarded-For спуфинг.** `RATE_LIMIT_TRUST_PROXY` дефолт сменён с `true` на `false` — доверие прокси теперь только там, где nginx реально стоит перед бэкендом (`docker-compose.prod.yml` включает явно).
- [x] **HIGH/MEDIUM — WS полностью исключён из rate limiting.** Handshake `/ws` теперь под тем же HTTP rate limiter, что и REST. Добавлен per-connection message-level token bucket (`message_limiter.go`, 5 msg/s, burst 10) — превышение много раз подряд рвёт соединение. Добавлен лимит на число одновременных соединений на пользователя (`Hub.CountFor`, 5).
- [x] **LOW — log injection в pretty-логгере.** `renderValue` теперь квотирует строки с control-символами (`\n`, `\r` и т.д.), не только с пробелами — подделка записей лога через непечатаемые символы больше невозможна.
- [ ] **LOW — JWT в query string WebSocket** (`?token=...`, может осесть в логах прокси/CDN). Фикс требует переноса на `Sec-WebSocket-Protocol` на клиенте и сервере — сознательно отложено по решению пользователя, риск принят (nginx в этом деплое query string не логирует).
- Всё остальное — SQL-инъекции, JWT alg confusion, mass assignment, race conditions на XP/стриках/промокодах, timing-атаки на логин, CSRF, auth middleware bypass, path traversal при загрузке фото — проверено, проблем не найдено.

**Прицельный аудит фичи модерации** (домен/провайдер/pipeline из P0) проведён в рамках прицельной проверки самой фичи при её разработке — prompt injection, SSRF, fail-open поведение — см. пункты P0 выше.

## P1 — Киллер-фича: «Находки Ноти»

Енот — барахольщик: тащит домой блестящие сокровища. Авито — и есть сокровища вторых рук. Раз в день Ноти «гуляет по маркетплейсу» и приносит хозяину узелок с находками.

**Почему это киллер-фича, а не ещё одна механика:**

- Прямой ответ на вопрос кейса «как конвертировать заходы в игру в конверсию на Авито»: находки ведут в просмотры, избранное, контакты — основные действия доски.
- Ежедневный повод вернуться: завтра узелок новый. Привычка — первая бизнес-цель кейса.
- Бренд: питомец не абстрактный — он делает то, что делает Авито: находит нужное. Заявка на номинацию за креативность.
- Синергия с готовой экономикой: переходы по находкам двигают квесты `view_five`/`favorite_three`, дедупликация XP уже есть (`xp_events`) — читов не добавляем.

Рассмотренные альтернативы: гардероб питомца (красиво, но не конвертирует в действия на доске — ушёл в бэклог), «только ИИ-модерация» (инфраструктура, а не переживаемая пользователем фича), пуш-уведомления (retention без конверсии, технически дорого в срок). Находки выигрывают по формуле «привычка × конверсия × бренд × реализуемость за день».

**Механика:**

- [ ] 3 находки в день: 2 по интересам (категории избранного и просмотров), 1 «блестяшка» — случайная из чужой категории (серендипность, расширяет спрос).
- [ ] Детерминированный подбор от (userID, дата) — тот же паттерн fnv-хэша, что в `DailyQuests` (`quest.go:43`). Повторный запрос — те же находки, честно и кэшируемо.
- [ ] Открытие узелка: +2 XP раз в день (через существующий журнал действий). Дальше — обычные просмотры/избранное.
- [ ] Реплика Ноти к каждой находке «почему принёс»: шаблоны по правилам; при наличии ключа — генерация LLM от лица Ноти (кэш на день, fail-safe на шаблоны).

**Реализация:**

- [ ] Бэкенд: `GET /api/v1/pet/finds`, `POST /api/v1/pet/finds/open`; домен — подбор и детерминизм; отбор кандидатов из read-model item (только `published`).
- [ ] WS-событие `finds.ready` после чек-ина — узелок появляется в реальном времени (усиливает требование кейса про WebSockets).
- [ ] Фронт: узелок на дашборде питомца с анимацией появления, карточки находок, реплики Ноти, бейдж «новое» до открытия.
- [ ] Тесты: домен (детерминизм, подбор категорий, исключение своих объявлений), app, api, компоненты фронта, i18n ru/en.
- [ ] Демо для жюри: у демо-аккаунтов заполнено избранное → находки осмысленные с первого входа.

## P1.5 — ИИ-слой (критерий «интеграция ИИ» + креативность)

Принцип: продукт полноценен без API-ключа; ИИ добавляет магию, эвристики держат базу.

- [ ] **Советы Ноти по твоим объявлениям** — апгрейд существующего `Advice` (`summary_advice_test.go`): конкретика по правилам (нет фото → «добавь фото», описание короче N → «расскажи подробнее», цена сильно выше медианы категории → «проверь цену»), формулировка — LLM в голосе Ноти. Выполнил совет → готовое действие `ActionItemImproved` → XP. Игра улучшает качество контента маркетплейса — вторая петля конверсии.
- [ ] **Записка от Ноти** — ежедневная сводка (уже есть) генерируется ИИ как личное письмо от питомца: что изменилось, чем помочь ему сегодня. Шаблонный fallback остаётся.
- [ ] **ИИ-модерация** — из P0; в README честно описать все три точки применения ИИ в продукте + использование в разработке (раздел уже начат, `README.md:492`).

## Ответ организаторам (черновик)

Провокационные объявления опубликовал внешний пользователь через открытую регистрацию — контент не наш и был снят сразу после обнаружения. Выводы сделаны системно: публичный контент прошёл через режим песочницы (пользовательские объявления видны только автору), добавлена ИИ-модерация с fail-closed поведением и rate limiting; меры описаны в README в разделе Trust & Safety.
